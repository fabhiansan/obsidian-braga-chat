## Description

Expand the tool set beyond CRUD (Create, Read, Update, Delete) into **knowledge management** — the networked thought, metadata intelligence, bulk operations, templating, and vault maintenance capabilities that make Obsidian a "second brain."

The current 13 tools handle file-level operations well. These additions let the agent understand **connections between notes** (backlinks, outlinks), manage **YAML frontmatter** (tags, aliases, properties), perform **bulk reorganization**, apply **templates**, and run **maintenance diagnostics** (broken links, orphaned notes).

## Completion Criteria

### Phase 1: Networked Thought Tools (Obsidian Links)

#### `get_backlinks(path)`
- ⬜ Returns all notes that link **to** the specified note
- ⬜ Uses `app.metadataCache.getBacklinksForFile(file)`
- ⬜ Returns array of `{ path, basename, linkText }` for each backlink
- ⬜ Formatted as markdown table in `formatToolResult`
- ⬜ Handles notes with zero backlinks gracefully (empty list, not error)

#### `get_outlinks(path)`
- ⬜ Returns all notes that the specified note links **to**
- ⬜ Uses `app.metadataCache.getFileCache(file)?.links`
- ⬜ Distinguishes internal wiki-links (`[[Note]]`) from external URLs
- ⬜ Returns array of `{ path, basename, linkText, displayText, original }`
- ⬜ Formatted as markdown table

#### `find_unlinked_mentions(query)`
- ⬜ Searches vault for text matching a note's title/alias that isn't currently linked
- ⬜ Uses `app.metadataCache` to find mentions + checks if already wrapped in `[[...]]`
- ⬜ Returns array of `{ notePath, lineText, lineNumber, context }`
- ⬜ **Killer feature** for building a second brain — discovers implicit connections

### Phase 2: YAML Frontmatter (Properties)

#### `get_yaml_properties(path)`
- ⬜ Reads YAML frontmatter from a note
- ⬜ Uses `app.metadataCache.getFileCache(file)?.frontmatter`
- ⬜ Returns parsed properties as `{ [key: string]: any }`
- ⬜ Handles notes with no frontmatter (returns `{}`)

#### `update_yaml_properties(path, properties)`
- ⬜ Updates specific YAML keys without rewriting the entire note body
- ⬜ Merges new properties with existing (doesn't destroy untouched keys)
- ⬜ Supports nested properties via dot notation: `"status.draft": true`
- ⬜ Preserves original YAML formatting and comments where possible
- ⬜ Can add, modify, or delete properties (delete via `null` value)

#### `set_yaml_property(path, key, value)`
- ⬜ Convenience wrapper for single property update
- ⬜ Validates value type against expected Obsidian types (string, number, boolean, array, date)

### Phase 3: Tag Operations

#### `search_tags(tag_name)`
- ⬜ Returns all notes containing a specific `#tag` or frontmatter tag
- ⬜ Uses `app.metadataCache.getTags()` or frontmatter `tags` field
- ⬜ Supports tag hierarchy: `#parent/child` matches `#parent/child/sub` too
- ⬜ Returns formatted list with note paths and contexts

#### `batch_add_tag(paths[], tag)`
- ⬜ Adds a tag to frontmatter `tags` array for multiple notes
- ⬜ Skips notes that already have the tag (idempotent)
- ⬜ Returns summary: `{ added: number, skipped: number, failed: number }`

### Phase 4: Bulk Operations

#### `bulk_move_notes(paths[], new_folder)`
- ⬜ Moves multiple notes to a target folder in one operation
- ⬜ Creates target folder if it doesn't exist
- ⬜ Handles name collisions (appends number: `Note (1).md`)
- ⬜ Returns summary: `{ moved: number, errors: { path, reason }[] }`

### Phase 5: Templating

#### `apply_template(path, template_name)`
- ⬜ Applies an Obsidian template to a note
- ⬜ Resolves template from `Templates/` folder or user-configured template directory
- ⬜ Supports template variables: `{{title}}`, `{{date}}`, `{{time}}`
- ⬜ Can create a new note from template or apply template to existing note
- ⬜ Integrates with Obsidian's native Templates or Templater plugin (if available)

### Phase 6: Maintenance Diagnostics

#### `find_broken_links()`
- ⬜ Scans vault for wiki-links pointing to non-existent notes
- ⬜ Uses `app.metadataCache.getFileCache(file)?.links` + checks file existence
- ⬜ Returns array of `{ sourcePath, brokenLinkText, lineNumber }`

#### `find_orphan_notes()`
- ⬜ Identifies notes with zero backlinks AND zero outlinks
- ⬜ "Islands" in the knowledge graph — disconnected notes
- ⬜ Returns array of `{ path, basename, created, modified }`

### Phase 7: Integration Test
- ⬜ Full workflow: "What concepts connect to my LQG research?" → `get_backlinks` → `get_outlinks` → `find_unlinked_mentions`
- ⬜ Metadata workflow: "Tag all notes from today's session with #research" → `batch_add_tag`
- ⬜ Maintenance workflow: "Find broken links" → `find_broken_links` → `create_note` to fix

## Architecture

### Obsidian API Map

| Tool | Obsidian API | Notes |
|------|-------------|-------|
| `get_backlinks` | Reverse lookup in `metadataCache.resolvedLinks` | Public resolved-link index maps source paths to destination paths and counts; filter sources targeting the requested note. |
| `get_outlinks` | `metadataCache.getFileCache(file)?.links` | `ReferenceCache[]` with `link`, `displayText`, `original` |
| `find_unlinked_mentions` | `metadataCache.getFileCache(file)?.embeds` + custom text search | Complex — needs to match aliases too |
| `get_yaml_properties` | `metadataCache.getFileCache(file)?.frontmatter` | Parsed object. `null` if no frontmatter. |
| `update_yaml_properties` | `vault.read()` + `vault.modify()` + YAML parser | Need `yaml` library or hand-roll parser |
| `search_tags` | `metadataCache.getTags()` | Returns `Map<string, { path: string }[]>` |
| `batch_add_tag` | `vault.read()` + parse frontmatter + `vault.modify()` | Same YAML challenge as above |
| `bulk_move_notes` | Loop over `fileManager.renameFile()` | Already have `move_note` — just batch it |
| `apply_template` | `app.internal...` or Templates plugin API | May need plugin integration |
| `find_broken_links` | `metadataCache.getFileCache(file)?.links` + `vault.getAbstractFileByPath()` | Check each link target exists |
| `find_orphan_notes` | Combine backlink + outlink counts | Simple computation after Phase 1 |

### YAML Challenge
Obsidian notes use YAML frontmatter:
```yaml
---
title: Quantum Gravity Draft
status: draft
tags: [physics, lqg]
aliases: ["QG Draft", "Gravity Paper"]
---
Note body here...
```

Options for parsing/writing:
1. **Add `yaml` dependency** — `js-yaml` is robust but adds bundle size (~20KB)
2. **Hand-roll simple parser** — Regex-based, handles common cases, lighter weight
3. **Use Obsidian's internal API** — `app.metadataCache` reads YAML but doesn't write it

**Recommendation:** Add `js-yaml` as dependency. Frontmatter is too important to get wrong with regex.

## Design Decisions

1. **Backlinks/outlinks return paths, not just basenames** — learned from T13 fix: folder context matters.
2. **YAML updates are merge-based** — `update_yaml_properties` only touches specified keys, preserves everything else.
3. **Tag search checks both `#inline` and frontmatter `tags`** — Obsidian supports both.
4. **Bulk operations are atomic-ish** — if one move fails, others continue. Summary shows what succeeded/failed.
5. **Template resolution is configurable** — default to `Templates/` folder, but allow user override in settings.
6. **Unlinked mentions searches aliases too** — if a note has `aliases: ["QG", "Quantum Gravity"]`, search for all variants.
