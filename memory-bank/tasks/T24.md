## 2026-09-19 — Index-Only Startup (99860e6)

Boot now reads only `sessions/index.json` (~57ms on device for 162 sessions,
down from ~8.9s of per-file reads). Message files hydrate lazily: background
for open/active tabs, on first open otherwise.

- `JsonlStorage.loadChatData(opts?: { hydrate?: boolean })` — default
  index-only: `messages: []`, `messageCount` from index, `hydrated: false`;
  unhydrated entries tracked in `unhydratedSessions` map.
- `hydrateSession(id)` — single-file read; concurrent callers share one read
  (`pendingHydrations`); records true message ids so the next save can append.
- **Hard save guard:** an unhydrated session is never written — its index
  entry is carried forward (title/scrollPosition updates allowed). Sessions
  that gained messages unhydrated (sync `onSessionDownloaded`) write as full
  overwrite. `lastSavedState` messageIds = `null` at boot so the first write
  can never take a bad append path.
- Boot/autosave/prune filters + SessionPickerModal use `sessionMessageCount()`
  (`messageCount ?? messages.length`) so unhydrated sessions stay visible.
- Open gate (`useSessionActions.openSessionInTab`) and send gate
  (`useMessageActions.handleSend`) await hydration and **write through
  `sessionsRef` synchronously** — `TurnLifecycle` reads the ref directly.
- Full-load consumers opt into `{ hydrate: true }`: sync `_populateSyncCache`,
  pluginDataSync usage-stats, diagnostics (2 sites). Title maps stay index-only.
- Types: `ChatSession.messageCount?` / `hydrated?`. 6 new storage tests incl.
  hard-guard and concurrent-hydrate cases. Suite 506/506, tsc + build clean.
- Device-verified: `[Startup] loadChatData resolved in 57ms`; 162 sessions /
2191 messages restored. Next bottleneck identified: SyncEngine WebDAV init
~4.1s (candidate for future non-blocking init).

## 2026-09-21 — Hydration Retry + Indexed Picker Count (device-verified)

Index-only startup follow-ons, found during T42g device testing on T42g (synced sessions opened empty; later text sends in image conversations demanded an image model):

- `20ae983` — `_hydrateSessionImpl` (ChatStorage): a failed read, or a 0-message read when the index expects N, **no longer marks the session hydrated**. The session stays unhydrated, retries on next open, and logs; partial reads warn. Companion: `useSessionActions.ts` silent `.catch(() => {})` → console.error + Notice "Failed to load session messages — will retry on next open". Root cause of the permanent-empty synced session: one bad first read at boot locked the session as "hydrated" for its lifetime.
- `1fb9263` — `SessionPickerModal.tsx`: the preview line hardcoded "No messages" for any session not in memory, contradicting the (already index-backed) meta count. Now renders "N messages — open to view" from `messageCount` when `hydrated === false && msgCount > 0`. Zero file reads — the index loads once at boot. Regression test: unhydrated fixture (messageCount 3) → shows count, no "No messages".

## 2026-09-22 Sync hydration follow-up

After sync, the metadata refresh could replace loaded React sessions with
empty index-only copies. Storage could also know a downloaded file was written
while the lazy hydration map no longer contained an entry for it. The final
fix preserves loaded messages during refresh and falls back to a pure disk
peek when opening a downloaded session. Regression coverage is in
`src/hooks/__tests__/useSessionActions.test.ts`.

## 2026-09-22 Session Truncation Safety Follow-up

- 3ae26c4 added hydration start, success, empty-result, and disk-peek
  diagnostics without logging message contents.
- 7291665 made the positive-count empty-write guard independent of transient
  hydration bookkeeping. Metadata-only or partial snapshots cannot overwrite
  a non-empty JSONL payload or truncate the authoritative index.
- Session omission is no longer treated as deletion. User deletion, remote
  deletion, and clear-all paths carry explicit deletion IDs.
- Automatic retention pruning was removed from new-session creation so a
  retention setting cannot silently remove persisted history.
- Verification: 571 tests, TypeScript, and production build passed. The
  repaired build was device-tested through a 202-session download-only
  recovery with no sync errors.

## 2026-09-28 Draft Attachment Storage Follow-up

Chat drafts may now persist before the first message is sent. The JSONL index
stores draft text and a reference to a separate per-session `.draft.json` file
for attachment payloads. This keeps image data out of the session index and
supports cleanup on draft clear or session deletion. See T31 and
[`chat-session-persistence.md`](../implementation-details/chat-session-persistence.md).
The production build passed; automated tests and live Obsidian/mobile
acceptance were not run for this follow-up.

## 2026-09-29 Empty-Write Guard Log Hygiene

The positive-count empty-write guard remains in place. When lazy-loaded,
unhydrated sessions are omitted from a save snapshot, JSONL storage now counts
the protected sessions and emits one Debug summary per save instead of one
warning per session (`e367c01`). This reduces log noise without weakening the
data-loss protection. Production build passed; no tests or live acceptance were
run for this logging-only change.
