# T31: Chat Input Draft Auto-Save

*Created: 2026-07-29*
*Last Updated: 2026-09-28 12:35:16 IST*
**Status**: ✅ **COMPLETED**
**Priority**: medium

## Problem

If the user has started typing a message but the app exits, crashes, or the plugin reloads before sending, the partially-typed text is lost. There is no recovery mechanism.

## Solution

Persist the current composer text as a `draft` field on the active `ChatSession`. The draft is saved debounced (500 ms) and restored when the session becomes active again.

## Scope

- Add `draft?: string` to `ChatSession` interface.
- In `ChatInput`: accept `draft` as an initial value; call `onDraftChange(text)` on every `handleInputChange` (debounced by the parent).
- In `ChatApp`: pass `activeSession?.draft` into `ChatInput`; debounce `setSessions` updates to write the draft; clear the draft on successful `onSend`.
- The existing `useChatSession` / `SessionStorage` pipeline will persist `draft` automatically because it is part of the session object.
- Drafts are isolated by session, including unsent attachment lists.
- Draft text and attachments restore after plugin restart. JSONL storage keeps attachment payloads in a separate per-session draft file so image data does not inflate the session index.
- Legacy-to-JSONL migration preserves draft text and attachment payloads.

## Files

## 2026-09-28 Draft Isolation and Attachment Persistence

The original text-only draft behavior is extended: each chat owns its own
composer, and unsent text and attachments survive restart. Clearing or deleting
a draft-only session cleans up its persisted draft attachment file. See the
session-scoped composer and storage details in
[`chat-ui-features.md`](../implementation-details/chat-ui-features.md) and
[`chat-session-persistence.md`](../implementation-details/chat-session-persistence.md).
