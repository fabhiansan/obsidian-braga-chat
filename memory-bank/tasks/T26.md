## Description
Upgrade obsidian-ai from a stateless chat assistant to a context-aware agent that remembers who the user is, learns from conversations, retrieves past sessions, and bridges to other Obsidian plugins. This is the "intelligence layer" that gives the plugin an OpenClaw-like sense of continuity and awareness.

**Key constraint:** All memory files, persona data, and learned context live in the **plugin directory** (`.obsidian/plugins/obsidian-ai/`), NOT the main vault. This keeps AI metadata separate from user notes.

---

## Design Philosophy

OpenClaw's intelligence comes from a **feedback loop**:
1. Conversation happens → agent extracts learnings → writes to files
2. Next session → agent reads those files → behavior changes
3. User corrects → agent updates files → loop continues

obsidian-ai must replicate this loop within Obsidian's constraints (no cron, sandboxed to vault). The loop becomes:
1. Chat session → auto-summarize at end → write to plugin memory DB/files
2. New chat session → load persona + memory into system prompt
3. AI uses `create_memory` tool during chat → memory grows

## Implementation

### Phase 1: Persistent Identity & Memory (P1)
**Status:** ✅ COMPLETE (2026-07-22)
**Note:** Implementation took ~2h but much of that was TypeScript type debugging. Core functionality is:
- Settings UI with toggle
- PersonaLoader reads persona.md + memory.md, injects into system prompt
- AI can call `create_memory` tool to append facts to memory.md
- AI can call `search_past_sessions` to search JSONL session history

**What works:**
- [x] `persona.md` injected into every chat session prompt
- [x] `memory.md` injected alongside persona (within token budget)
- [x] `create_memory` tool persists entries with timestamp + category + tags
- [x] `search_past_sessions` searches session JSONL via existing SearchIndex

**What's missing / next:**
- [x] Auto-session summarization implementation is wired at session end; runtime acceptance remains to be recorded
- [ ] Proactive memory (AI decides what to remember without explicit user request)
- [ ] Memory viewer UI in chat sidebar
- [ ] Plugin bridges (Dataview, Tasks)

**SessionSummarizer.ts:**
- `summarizeSession(sessionId: string, messages: ChatMessage[]): Promise<MemoryEntry>`
- Called on session end (or when user clicks "Save Memory")
- Uses a cheap/fast model call with summarization prompt:
  ```
  Summarize this conversation into 3-5 bullet points of things 
  worth remembering about the user or their work.
  ```
- Extracts: topics discussed, user preferences revealed, decisions made, project updates

**create_memory tool:**
```typescript
export const createMemoryTool = t({
  description:
    "Create a persistent memory about the user, their preferences, " +
    "or insights from the conversation. Use when the user shares " +
    "something worth remembering for future sessions.",
  inputSchema: z.object({
    category: z
      .enum(["user_fact", "project", "preference", "insight", "reference"])
      .describe("Type of memory"),
    content: z.string().describe("The memory content — be specific and concise"),
    tags: z
      .array(z.string())
      .optional()
      .describe("Optional tags for organization (e.g. ['physics', 'qhe'])"),
  }),
});
```

**ToolExecutor behavior:**
- Appends to `.obsidian/plugins/obsidian-ai/intelligence/memory.md` as markdown bullet
- Also writes to SQLite `memories` table if DB mode enabled
- Format: `- [YYYY-MM-DD] **{category}**: {content} #tag1 #tag2`

**Architecture:**
```
Plugin Directory
└── intelligence/
    ├── memory.json          ← canonical structured storage
    ├── memory.md            ← human-readable mirror (auto-generated)
    └── memory-audit.jsonl   ← append-only operation log
```

**Key decisions:**
- `memory.json` is the single source of truth; `memory.md` is a read-only export
- Audit log is for human oversight, not AI consumption (disabled by default)
- All memory operations go through `MemoryStore` which handles both JSON and markdown sync

### Phase 2.5: Memory Deduplication & Optimization (P2.5)
**Status:** ✅ COMPLETE (2026-08-14)

**Problem:** MemoryStore.create() accumulated duplicates over months. Same facts repeated 10-20×. File grew to 184 KB.

**Solution (two-layer):**
- **Write-time deduplication:** Jaccard similarity at 70% threshold, category-scoped. Prevents future duplicates automatically.
- **Historical cleanup:** Manual "Prune Duplicates" button using Jaccard + "AI-Powered Prune" using LLM semantic clustering.
- **AI Prune:** Per-category batching (one API call per category). Progress modal with live logs, ETA, cancel button. Reverted single-prompt batching after it hung indefinitely (5+ min, no response).

**Files:**
- `src/intelligence/MemoryStore.ts` — dedup + prune
- `src/intelligence/MemoryOptimizer.ts` — AI clustering
- `src/components/presentational/AIPruneModal.tsx` — progress UI
- `src/settings-sections/intelligence.ts` — optimization controls

**Tests:** 40 MemoryStore tests + 7 MemoryOptimizer tests

**Status:** ⏸️ PARTIAL — explicit search tool exists; automatic retrieval remains pending

**Files:**

**search_past_sessions tool:**
```typescript
export const searchPastSessionsTool = t({
  description:
    "Search past chat sessions by topic, keyword, or content. " +
    "Use when the user references something from a previous conversation " +
    "or when you need historical context.",
  inputSchema: z.object({
    query: z.string().describe("Search query"),
    limit: z
      .number()
      .optional()
      .describe("Max results (default 5)"),
  }),
});
```

**ContextRetriever.ts:**
- `findRelevantSessions(query: string, limit?: number): Promise<SessionSnippet[]>`
- Uses existing SearchIndex (inverted index from JSONL) — already built for T24
- Returns: session title, date, and top 3 matching snippets
- Injected into context before user message when query seems to reference past work

**Smart injection heuristic:**
- If user message contains "remember when", "last time", "as we discussed", "my previous" → auto-search
- Otherwise, include only if `search_past_sessions` is explicitly called

### Implementation audit — 2026-08-29

The source tree is ahead of some older task wording:

- `SessionSummarizer` is implemented and called by the session-end storage
  path when `autoSummarize` and the intelligence layer are enabled. Runtime
  acceptance of the generated memories is not recorded here.
- `search_past_sessions` is implemented through `SearchIndex` and excludes the
  active session. `ContextRetriever.ts` and phrase-based automatic injection
  are not present, so cross-session retrieval is currently explicit.
- `identityContextBudget` is stored and editable in settings, but
  `buildSystemPrompt()` does not pass it to `loadFullContext()`. The loader
  therefore uses its 2,000-token default unless a caller supplies a budget.
- The hot/cold `core.json` / `archive.json` split, ranked `index.json`,
  recency-importance-frequency curation, proactive memory, and peer-plugin
  bridges remain design or future work.

The current implementation is therefore a persistent, user/agent-invoked
memory store with optional end-of-session extraction, not yet an autonomous
or tiered agentic-memory system.

### Phase 4: Obsidian Plugin Integration (P4)
**Status:** ⏸️ PENDING — architecture moved to T39
**Goal:** AI can use compatible peer-plugin capabilities — becoming a true vault agent.

**Architecture decision (2026-08-05):** Do not add one-off private-plugin
bridges directly inside T26. T39 defines a versioned Integration Provider API:

### Phase 5: Proactive Suggestions (P5)
**Status:** ⏸️ PENDING  
**Goal:** Limited proactivity while Obsidian is open.

**Constraints:** No cron while Obsidian is closed. Best effort while open.

**Hooks:**
- **On vault open:** Check for stale tasks (via TasksBridge), show notice: "3 tasks due today"
- **On idle (>5 min):** Offer to summarize long session if >20 messages
- **On note creation:** If note matches a project tag from memory, suggest: "Link this to your QHE project?"

**Implementation:** Obsidian workspace events + setTimeout debouncing.
